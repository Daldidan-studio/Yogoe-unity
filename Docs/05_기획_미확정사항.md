# 구현 전에 확정해야 할 기획 이슈

MVP2차 기획서 리뷰 중 발견한, 코드 구조에 영향을 주는 미확정/모순 항목.
해당 시스템 작업 시작 전에 반드시 확인할 것.

## 1. [결정] 친밀도 상승폭 불일치 (5-1 vs 5-4)
- (결정) "직접 먹이는 선호 공양"은 **+0.25**로 확정.
- 정리하면: 직접 공양(5-1①) = +0.25 / 요구 들어주기(5-1②, 10장) = +0.5 /
  윷놀이 말 이동(5-1③, 11장) = +0.25. 5-4 표의 +0.5는 직접 공양 경로에는 적용하지 않음.
- 코드 반영 완료: `OfferingData.intimacyGain` 기본값 0.25로 수정.

## 2. [결정] 친밀도 최소 단위 모순
- (결정) "최소 단위 0.5" 개념 자체를 삭제. 별도의 최소 단위 규칙 없이,
  경로별로 위 1번에서 정한 값(0.25 또는 0.5)만큼 그대로 증가시키면 됨.

## 3. [결정] 윷놀이 승리조건 (11장)
- (결정) (A) 내 말 아무거나 하나만 골인하면 즉시 승리/보상 지급. 팀 전체 골인은 요구하지 않음.
- 유저 팀 3~4말 vs 이무기 1말 구도에서 유저 쪽이 유리한 방향으로 확정된 것 — 온보딩 게이트(3번째 향)
  난이도도 이 기준으로 설계.
- 남은 구현 과제: 말 여러 개 중 "하나 골인 시 즉시 라운드 종료" 판정 로직, 나머지 대기 중이던 말 처리(그대로
  둘지 리셋할지는 미정 — 필요시 추가 확인).

## 4. [결정] 괴 단계 제거 + 넋 기력·진화 조건
- (결정) 괴 단계 제거 — 넋 → 혼 2단계. 코드(GrowthStage enum) 반영 완료.
- (결정) 넋 기력은 **정화수로만** 채운다. 시간 경과 자연 감소 없음.
  → 넋은 행동 상태머신 제외(고정 도깨비불) 현행 코드 가정이 맞음.
- (결정) 넋 → 혼 진화 조건: **기력 100 도달 시 즉시 혼**. 친밀도는 0부터 시작.
  → 기존 임시 구현이 최종 스펙. 추가 확인 불필요.

## 5. [결정] 기절 시 요구 삭제
- (결정) 10장 **[확정]** 태그로 진행. 기절 시 요구 삭제(세션 간 유지 안 됨).
  6-2 [제안] 표기는 무시하고 확정 규칙을 따른다.

## 6. 윷놀이 특수 칸 보상 구조
- "공양물1·정화수1·엽전1 확정수급"이 칸 하나당 3종 다 주는지, 칸 종류별로 다른지 불명확 (GDD 12-1 참조만 되어있음)

## 7. 말업기(스택) 관련 미정
- 스택된 말 이동 시 친밀도 +0.25가 스택 내 각 요괴에게 개별 적용되는지, 1회만인지
- 이무기가 스택을 잡으면 스택 전체가 잡히는지

## 8. 공덕더미 단계 / 상점 리셋 비용의 "동적 기준값"
- 7-2 더미 단계 경계, 12장 상점 리셋 비용 모두 "현재 생산속도 기준 N분치"로 계산됨
- 친밀도·기물 레벨이 바뀌면 같은 공덕 보유량도 단계/비용이 달라 보일 수 있음
- 하나의 공용 계산 함수로 통일 권장 (`GameEconomy.GetCurrentProductionRate()` 같은 단일 소스)

## 9. 혼잣말 vs 요구 말풍선 동시 표시 우선순위 없음 (6-4, 10장)
- 둘 다 캐릭터 머리 위에 뜰 수 있는데 우선순위/시각적 구분 규칙 없음
- 탭 반응도 다름: 요구=단일탭으로 상세이동, 혼잣말=탭하면 문구 갱신(더블탭해야 상세이동)
