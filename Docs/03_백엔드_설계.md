# 백엔드 설계 — 신뢰 시각(오프라인 정산 치팅 방지)

세이브는 기기 로컬에 둔다(서버 저장 비용 회피). 서버는 **"지금이 진짜 몇 시인지"** 하나만
제공하는 최소 역할만 맡는다 — 유저가 기기 시계를 미래로 돌려 오프라인 방치 수익(기력 소모·
자원 생산, `00` 6-2·9장)을 부정하게 당기는 걸 막기 위함.

**[결정] 벤더: Firebase.** PlayFab은 2026-03 무료 한도가 (비Xbox 게임 기준) 10만→1,000
평생 계정으로 대폭 축소돼 제외. Supabase는 무료 한도가 더 후하지만(월 5만 MAU) 공식 Unity
SDK가 없어(커뮤니티 SDK만 존재) 제외. Firebase는 공식 Unity SDK가 안정적이고, 이 용도로 딱
맞는 기능(아래)이 있음.

---

## 1. 핵심 선택 — Realtime Database, Firestore 아님

Firestore는 서버 시각을 얻으려면 문서를 한 번 써야 하지만, **Realtime Database는
`.info/serverTimeOffset`**이라는 전용 경로가 있어 접속만 하면 클라이언트-서버 시간차(ms)를
바로 구독받는다 — 쓰기 없음, Cloud Function 없음, 이 용도로 정확히 만들어진 기능.

## 2. 구성 요소

| 요소 | 역할 |
|---|---|
| Firebase Realtime Database | `.info/serverTimeOffset` 구독 → offset(ms) 수신 |
| Firebase Authentication (익명 로그인) | RTDB 접근 규칙상 필요. 유저 식별 목적 아님. 나중에 계정 시스템을 붙일 때 이 익명 세션을 업그레이드하는 경로도 있어 확장성 있음 |

## 3. 클라이언트 흐름

1. 콜드스타트 시 Firebase 초기화 → 익명 로그인
2. RTDB `.info/serverTimeOffset` 구독 → `offsetMs` 획득
3. `TrustedNowUtc = DateTime.UtcNow + offsetMs`
4. 세이브에 저장해둔 직전 세션 종료 시점(`lastSeenTrustedUtc`)과 비교해 실제 경과 초
   (`elapsedSeconds`) 계산
5. 이 값을 오프라인 정산(기력 소모·자원 생산, `00` 6-2·9장)에 사용 — 로컬 시계가 아니라
   이 값 기준

## 4. [결정] 네트워크 실패 시 폴백 — 절충안(C)

서버 시각을 못 받을 때(오프라인/네트워크 불안정):

- 로컬 경과시간을 그대로 쓰되, **말이 안 되게 큰 폭**(예: 하루 이상 미래로 튐)일 때만 그
  폭을 클램프하고 나머진 로컬 시계를 신뢰한다.
- 근거: 로컬 시계 전면 신뢰(치팅에 취약)와 정산 전면 보류(네트워크 안 좋은 유저 불만) 사이의
  절충. 클램프 임계값(며칠까지 허용할지)은 구현 시 튜닝.

## 5. 코드 반영 지점 (구현 시 — 아직 미착수)

- `Assets/Scripts/Save/OfflineSimulator.cs` — 경과시간 계산을 `TrustedNowUtc` 기반으로 교체
- 신규 `Assets/Scripts/Core/TrustedTimeService.cs`(가칭) — Firebase 초기화·익명로그인·offset
  구독·`TrustedNowUtc` 노출, 싱글턴
- 필요 SDK: Firebase Unity SDK 중 **Auth + Database 모듈만** (Firestore·Analytics 등 불필요)

## 6. 비용

RTDB 무료 티어(동시연결 100·다운로드 10GB/월)로 충분 — 이 용도는 저장 데이터가 없어 사실상
안 걸림.
