# 02. 개발 진행 상황

> 이 문서는 2026-09 기준, "다시...나의 요괴들(My K-SPIRITS)" 설계에서
> "한 폭의 요괴" 설계(기획문서 MVP 2차 PDF)로 전환한 직후의 실제 상태를 정리한다.
> 과거 진행 기록은 `Docs/_legacy_kspirits/02_개발진행.md`에 그대로 남아있다.

## 0. 이번 전환에서 한 일 요약

기존 Yogoe-unity 프로젝트(유니티 셸, ProjectSettings, Packages, 이미 동작하는
GitHub Actions CI/CD)는 그대로 유지하고, 게임 로직/기획 관련 내용만
"한 폭의 요괴" 설계로 교체했다. 단, 두 설계 모두에 윷놀이 미니게임이
있어서 기존 코드 중 재사용 가능한 부분은 코드를 직접 읽어 검증한 뒤 남겼다.

## 1. 유지됨 (기존 코드 그대로 재사용)

- `Assets/Scripts/Minigames/Yut/YutBoardLayout.cs` — 29밭 좌표 계산, 지름길(참/모/뒷모/찌모/방) 좌표
- `Assets/Scripts/Minigames/Yut/YutBoardQuadrant.cs` — UI 레이아웃용 enum
- `Assets/Scripts/Minigames/Yut/YutMoveResolver.cs` — 도개걸윷모/빽도 이동 경로 계산 (지름길 진입 포함)
- `Assets/Scripts/Minigames/Yut/YutThrowRoller.cs` — 던지기 확률 테이블 (모1·빽도1·도3·개6·걸4·윷1 / 16)
- `Assets/Scripts/Minigames/Yut/YutMiniGame.cs` — 윷판 UI, 던지기 애니메이션, 말 표시, 후보 이동칸 강조 등
  화면/입력 담당 컴포넌트. `KSpirits.Core.GameConstants` 의존성만 제거하고
  `HeartMax` 값을 리터럴 5로 인라인 처리(주석 남김)해서 컴파일되게 패치함.
- 프로젝트 셸: `ProjectSettings/`, `Packages/`, `.github/workflows/build-and-deploy.yml`
  (Unity 6000.3.11f1, WebGL 빌드 → GitHub Pages 배포. 스크립트 경로에 의존하지 않으므로
  이번 이동/삭제 작업으로 인한 CI 영향 없음 — 확인 완료)

**주의**: 위 파일들은 "보드 계산 + 화면 표시"만 담당한다. 승패 판정, 상대(이무기) AI,
잡기(캡처) 로직, 점수/보상 지급은 원래 프로젝트에도 없었고 지금도 없다.
새 설계 기준으로 새로 만들어야 한다. (아래 4번 참고)

## 2. 새로 추가됨 ("한 폭의 요괴" 설계 기반, scroll_of_yoegoe에서 이식)

- `Assets/Scripts/Core/BigNumber.cs` — mantissa/exponent 기반 무한 자릿수 시스템,
  ㄱㄴㄷ...ㅎ → ㄱㄱ,ㄴㄴ... 순환 단위 표기
- `Assets/Scripts/Data/Enums.cs` — `GrowthStage{Neok,Hon}` (괴 제거 반영), `ActionState`,
  `CharacterId`, `OfferingKind`
- `Assets/Scripts/Data/{CharacterData,PropData,OfferingData}.cs` — ScriptableObject 데이터
- `Assets/Scripts/Characters/CharacterRuntimeStats.cs` — 캐릭터별 런타임 상태(성장단계/친밀도/기력/행동상태)
- `Assets/Scripts/Characters/{PropSlot,PropManager}.cs` — 기물 슬롯 점유/해제, 빈 기물 탐색
- `Assets/Scripts/Characters/CharacterAgent.cs` — 행동 상태머신(걷기→머무르기→늘어짐→기절),
  분당 생산 계산(친밀도·엔딩기물 보정 포함), 공양 수령 API
- `Assets/Scripts/Economy/GameEconomy.cs` — 공덕(재화) 누적/이벤트
- `Assets/Scripts/Debugging/TestSceneBootstrap.cs` — 아트 없이 프리미티브만으로
  캐릭터/기물을 배치해서 실제 빌드(WebGL 포함)에서 동작을 확인하기 위한 부트스트랩

## 3. 레거시로 이동됨 (`Assets/_Legacy_KSpirits/`, `Docs/_legacy_kspirits/`)

"다시...나의 요괴들" 설계 전용 코드 — 카드 소환, 대사 시스템, 튜토리얼, 저장 시스템,
족자 UI 등. 삭제하지 않고 참고용으로 보관.

**개별 재사용 가능성을 검증하지 않고 통째로 옮긴 것들** (컴파일 확인 불가 상태에서
보수적으로 판단): `Systems/SaveData.cs`/`SaveHost.cs`/`SaveService.cs`(저장 시스템),
`UI/ScrollScreenUI*.cs`(족자 UI 셸), `UI/DraggableOfferItem.cs`(드래그 공양 — 새 설계
5-3 공양 스펙과 개념이 유사해 나중에 재활용 검토 가치 있음), `UI/UIFont*.cs`.
지금은 활성 트리에서 빠져 있으므로 참고만 하고, 필요하면 개별적으로 다시 가져올 것.

## 4. 즉시 해야 할 일 (Unity Editor에서, 유저 작업)

`Assets/Scenes/Boot.unity`가 레거시로 이동되면서 **현재 활성 씬이 0개**다.
`ProjectSettings/EditorBuildSettings.asset`의 Build Settings 씬 목록도 비워뒀다
(존재하지 않는 씬 경로를 참조한 채로 두면 CI 빌드가 실패할 수 있어서).

→ Unity Editor에서 새 씬을 만들고, 빈 GameObject에 `TestSceneBootstrap`을 붙인 뒤
Build Settings에 등록해야 다음 CI 빌드(WebGL)가 실제로 뭔가를 보여준다.
(이전에 설명한 것과 동일한 방식 — 아트 에셋 없이도 캡슐/큐브로 확인 가능)
