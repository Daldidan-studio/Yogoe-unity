# 06. 코드 공부 노트 — 요괴 코드 도감

> 이 문서는 유니티/C#을 모르는 상태에서 이 프로젝트 코드를 공부하려는 사람을 위해 쓴다.
> 지금까지 만든 코드를 처음 배우는 눈높이로 정리했고, 낯선 용어는 나올 때마다 먼저 풀어서
> 설명한다. 순서대로 읽어도 되고 궁금한 장만 찾아 읽어도 된다.
> (같은 내용을 보기 편한 웹페이지로도 만들어 뒀다 — 대화에서 전달된 아티팩트 링크 참고.)

## 0장. 이 문서 보는 법 & 미니 용어 사전

코드 설명 중에 낯선 단어가 나올 때마다 여기부터 훑어보자. 이후 장에서는 이 단어들을 따로
설명하지 않고 바로 쓴다.

- **클래스 (class)**: "설계도"다. `CharacterAgent`라는 클래스는 "캐릭터가 할 수 있는 행동들"을
  적어둔 설계도이고, 실제 게임 화면에는 이 설계도로 찍어낸 옥토끼·삼족오·구미호라는 세 개의
  "실물"이 따로따로 움직인다. 설계도는 하나, 실물은 여러 개일 수 있다.
- **MonoBehaviour**: 유니티가 "이 설계도는 화면의 오브젝트에 직접 붙여서 쓸 수 있다"고
  인식하게 해주는 기본 설계도. `public class CharacterAgent : MonoBehaviour`라고 쓰면
  "CharacterAgent는 MonoBehaviour의 능력을 물려받는다"는 뜻이고, 그 덕분에 `Awake()`,
  `Update()` 같은 자동 호출 함수를 쓸 수 있다.
- **public / private**: `public`은 "다른 스크립트에서도 볼 수 있고, 유니티 에디터의
  Inspector 창에도 노출되어 숫자를 직접 바꿀 수 있음". `private`은 "이 스크립트 안에서만
  사용, 바깥에서는 손댈 수 없음".
- **필드(field) / 메서드(method)**: 필드는 클래스가 들고 있는 값 하나
  (`public float moveSpeed = 2f;` → "moveSpeed라는 소수 값을 2로 시작해서 저장"). 메서드는
  이름 붙은 동작 뭉치 (`private void TickWalking(float dt)` → "TickWalking이라는 동작,
  dt라는 숫자를 하나 받고 아무것도 돌려주지 않는다").
- **Awake / Start / Update**: 유니티가 정해진 타이밍마다 자동으로 불러주는 특수 메서드.
  `Awake()`는 오브젝트가 생기자마자, `Start()`는 씬의 모든 오브젝트가 Awake를 마친 다음
  첫 화면이 뜨기 직전에 한 번, `Update()`는 1초에 수십~수백 번 게임이 켜져 있는 내내
  반복된다 — 게임의 심장박동.
- **static**: "캐릭터 한 명 한 명이 따로 갖는 값"이 아니라 "그 클래스 전체가 공유하는
  창고 하나"에 있다는 뜻. `GameEconomy`는 전체가 static이라 게임 안에 재화 창고는 딱
  하나뿐이다.
- **enum**: 미리 정해둔 몇 가지 값 중 딱 하나만 될 수 있게 이름 붙인 목록. `ActionState`는
  Walking(걷기)·Staying(머물기)·Slumped(주저앉기)·Fainted(기절) 넷 중 하나.
- **배열 (array)**: 같은 종류의 값을 여러 개 담는 상자. `Sprite[] walkDown = new Sprite[4];`
  → "정면으로 걷는 그림 4장을 담는 상자".
- **null**: "아직 아무것도 안 들어있음"을 뜻하는 특수값.
- **ScriptableObject**: 유니티에서 "코드가 아니라 데이터"만 담아두는 특별한 상자. `.asset`
  파일로 저장되고, 코드를 안 건드리고도 Inspector에서 숫자·텍스트만 바꿔 밸런스를 조정할 수
  있게 해준다. `Okto.asset`, `Peach.asset` 같은 파일들이 여기 해당한다 (7장 참고).

## 2장. 캐릭터를 살아있게 만드는 것 — 상태머신

캐릭터 하나하나는 `CharacterAgent.cs`라는 설계도로 만들어진다. 핵심은 "지금 이 캐릭터가
네 가지 상태 중 어디에 있는지"를 계속 관리하는 것 — 이걸 **상태머신(state machine)**이라고
부른다.

```
걷기(Walking) --기물 도착--> 머물기(Staying) --기력 0--> 주저앉기(Slumped)
                                                        --12시간 경과--> 기절(Fainted)
```

기절한 캐릭터는 공양(먹이 주기)을 받아야만 다시 걷기 상태로 돌아온다
(`ReceiveOffering` 메서드).

### 매 프레임 하는 일 — Update()

```csharp
private void Update()
{
    if (Stats.Stage == GrowthStage.Neok) return; // 넋은 상태머신 대상 아님

    float dt = Time.deltaTime;
    switch (Stats.State)
    {
        case ActionState.Walking: TickWalking(dt); break;
        case ActionState.Staying: TickStaying(dt); break;
        case ActionState.Slumped: TickSlumped(dt); break;
        case ActionState.Fainted: /* 외부(공양)에서만 깨어남 */ break;
    }

    UpdateWalkAnimation(dt);
    UpdateStateDot();
    if (Stats.State != ActionState.Fainted) UpdateMonologue(dt);
}
```

> **Time.deltaTime**: "지난 프레임과 이번 프레임 사이에 실제로 몇 초가 지났는지"를 담고
> 있는 값. 이 값을 곱해서 움직이면 어떤 기기에서든 똑같은 속도로 보인다.

### 걷기 — 목적지를 정하고 그쪽으로 이동

```csharp
private void TickWalking(float dt)
{
    if (isWandering)
    {
        wanderTimer += dt;
        if (wanderTimer >= WanderRetrySeconds) { PickDestination(); return; }

        if (wanderTarget == null || Vector3.Distance(transform.position, wanderTarget.Value) < 0.05f)
        {
            wanderTarget = MapBounds.RandomPoint(transform.position.z);
        }
        transform.position = MapBounds.Clamp(
            Vector3.MoveTowards(transform.position, wanderTarget.Value, moveSpeed * dt));
        ResolveSeparation(dt);
        return;
    }

    if (destination == null) { PickDestination(); return; }

    Vector3 targetPos = destination.transform.position;
    transform.position = MapBounds.Clamp(
        Vector3.MoveTowards(transform.position, targetPos, moveSpeed * dt));
    ResolveSeparation(dt);

    if (Vector3.Distance(transform.position, targetPos) < 0.05f)
    {
        if (destination.TryOccupy(this))
        {
            currentProp = destination;
            destination = null;
            EnterStaying();
        }
        else
        {
            PickDestination(); // 밀린 쪽은 되돌지 않고 다음 후보로
        }
    }
}
```

> **잡았던 버그**: 예전 버전에서는 방황(`isWandering`) 분기가 타이머만 세고 실제로 위치를
> 옮기는 코드가 없었다. "정처 없이 돌아다녀야 하는데 다들 제자리에 멈춰 있다"는 문제가
> 있었는데, `MapBounds.RandomPoint`로 실제 목적지를 정해 `MoveTowards`로 이동시키도록 고쳤다.

### 겹치지 않게 밀어내기

`ResolveSeparation`은 "다른 캐릭터와 너무 가까우면 서로 반대 방향으로 살짝 밀어낸다"는
단순한 규칙이다. `ActiveAgents`는 "지금 씬에 존재하는 모든 캐릭터" 목록으로, 캐릭터가
켜질 때(`OnEnable`) 스스로 등록하고 꺼질 때(`OnDisable`) 빠진다.

```csharp
private void ResolveSeparation(float dt)
{
    Vector3 push = Vector3.zero;
    for (int i = 0; i < ActiveAgents.Count; i++)
    {
        var other = ActiveAgents[i];
        if (other == null || other == this) continue;

        Vector3 diff = transform.position - other.transform.position;
        diff.z = 0f;
        float dist = diff.magnitude;
        if (dist > 0.0001f && dist < SeparationRadius)
        {
            push += diff.normalized * (SeparationRadius - dist);
        }
    }

    if (push != Vector3.zero)
    {
        transform.position = MapBounds.Clamp(transform.position + push * SeparationSpeed * dt);
    }
}
```

## 3장. 기력이 줄어드는 원리

머물기 상태(`TickStaying`)에서 매 프레임 기력을 조금씩 깎는다. 기획서 6-2장 기준
"1분당 3 소모 = 20초당 1".

```csharp
private void TickStaying(float dt)
{
    Stats.StateTimer += dt;
    Stats.Stamina -= dt / 20f * staminaDrainMultiplier; // 20초당 1점 (디버그 배속 적용)

    if (Stats.Stamina <= 0f)
    {
        Stats.Stamina = 0f;
        EnterSlumped();
        return;
    }

    if (currentProp != null)
    {
        double perMinute = currentProp.GetBaseProductionThisLevel()
                            * GetIntimacyCorrection()
                            * GetEndingPropCorrection();
        GameEconomy.AddMerit(perMinute / 60.0 * dt);
    }

    if (Stats.StateTimer >= StayDurationSeconds)
    {
        LeaveCurrentProp();
        EnterWalking();
    }
}
```

> **지금 임시로 켜둔 디버그 값**: `staminaDrainMultiplier`는 기력이 줄어드는 걸 눈으로
> 바로 확인하시라고 임시로 **8배**로 켜둔 값이다 (1이면 기획서 그대로). 씬에 미리 배치된
> 오브젝트가 아니라 캐릭터가 생길 때마다 코드로 새로 만들어지는 값이라, 유니티 Inspector가
> 아니라 **`CharacterAgent.cs` 파일에서 `public float staminaDrainMultiplier = 8f;`의
> 숫자 8을 1로** 바꿔야 원래 속도로 되돌아간다.

### 생산량 공식 (기획서 7-1장)

```csharp
// 친밀도 보정 = 1 + 친밀도/100
private double GetIntimacyCorrection() => 1.0 + Stats.Intimacy / 100.0;

// 주인이 자기 엔딩 기물에 앉으면 x2
private double GetEndingPropCorrection()
{
    if (currentProp == null || currentProp.data == null) return 1.0;
    bool ownEnding = currentProp.data.isEndingProp && currentProp.data.owner == Data.id;
    return ownEnding ? 2.0 : 1.0;
}
```

### 탭이 백그라운드로 가도 시간이 멈추지 않게

브라우저 탭을 다른 탭으로 전환하면 웹지엘 프레임이 뜸해지는데, 유니티는 기본적으로 한
프레임의 시간 간격이 너무 크면 `Time.maximumDeltaTime`(기본 0.33초)만큼으로 잘라버린다.
그러면 탭이 비활성이던 동안 실제로 흐른 시간이 통째로 무시돼서 기력/생산이 멈춘 것처럼
보였다.

```csharp
// Main.cs Awake() 맨 앞
Time.maximumDeltaTime = 3600f;
```

이건 "게임을 켜둔 채 탭만 옮긴 경우"를 고치는 최소한의 방법이고, 앱을 완전히 껐다가 다시
켰을 때의 진짜 오프라인 정산(기획서 4장, 15장)은 세이브 시스템이 있어야 하는 별도 작업이다.

## 4장. 캐릭터가 돌아다니는 범위 — 맵과 카메라

### 맵 경계 — MapBounds

게임 전체가 공유하는(static) 사각형 범위 하나를 들고 있는 단순한 도구 클래스다.

```csharp
public static class MapBounds
{
    public static Vector2 Min = new Vector2(-100f, -100f);
    public static Vector2 Max = new Vector2(100f, 100f);

    public static void SetBounds(Vector2 min, Vector2 max) { Min = min; Max = max; }

    public static Vector3 RandomPoint(float z = 0f)
        => new Vector3(Random.Range(Min.x, Max.x), Random.Range(Min.y, Max.y), z);

    public static Vector3 Clamp(Vector3 pos)
    {
        pos.x = Mathf.Clamp(pos.x, Min.x, Max.x);
        pos.y = Mathf.Clamp(pos.y, Min.y, Max.y);
        return pos;
    }
}
```

### 배경을 화면에 딱 맞게 깔기

CSS의 `background-size: cover`와 같은 방식으로, 가로/세로 중 더 많이 늘려야 하는 비율을
골라 확대한다.

```csharp
float coverScale = Mathf.Max(camWidth / spriteWidth, camHeight / spriteHeight);
float scale = coverScale * Mathf.Max(1f, mapOverscan);
go.transform.localScale = new Vector3(scale, scale, 1f);
```

> **되돌린 부분**: 한때 `mapOverscan`(맵을 화면보다 일부러 더 키우는 배수)을 1.8로
> 넣었는데, "맵은 원래 크기대로 해달라"는 요청으로 기본값을 **1**(원본 크기, 카메라를
> 겨우 덮는 최소 배율만 적용)로 되돌렸다. 드래그로 둘러볼 수 있는 기능 자체는 남겨뒀다.

### 드래그로 맵 둘러보기 — MapCameraDrag

이 프로젝트는 유니티의 **새 Input System**만 쓰도록 설정돼 있어(예전 방식
`UnityEngine.Input`을 쓰면 오류) 이 방식으로 마우스/터치 위치를 읽는다.

```csharp
private static bool TryReadPointer(out Vector2 screenPos, out bool pressed)
{
    var mouse = Mouse.current;
    if (mouse != null && mouse.added)
    {
        screenPos = mouse.position.ReadValue();
        pressed = mouse.leftButton.isPressed;
        return true;
    }

    var touchscreen = Touchscreen.current;
    if (touchscreen != null && touchscreen.added)
    {
        var touch = touchscreen.primaryTouch;
        var phase = touch.phase.ReadValue();
        pressed = phase == TouchPhase.Began || phase == TouchPhase.Moved || phase == TouchPhase.Stationary;
        screenPos = touch.position.ReadValue();
        return true;
    }

    screenPos = default;
    pressed = false;
    return false;
}
```

> **사장님이 직접 찾아낸 버그**: 한동안 원인을 못 찾던 `RangeError: Maximum call stack
> size exceeded` 웹지엘 크래시의 원인은 `Pointer.current`였다. 이건 실제 장치가 아니라
> "마우스든 터치든 하나로 합쳐서 다루기 위한 가짜(합성) 장치"인데, 웹지엘 빌드에서 읽으면
> 브라우저 쪽 메모리 접근 오류로 죽는 경우가 있었다. `Mouse.current` / `Touchscreen.current`를
> 직접 읽도록 고쳐서 해결됐다.

## 5장. 기물과 자리 다툼

기물(가구) 하나하나는 `PropSlot` 컴포넌트로 표현된다. "누가 지금 앉아있는지"뿐 아니라
"누가 그쪽으로 오고 있는 중인지"까지 구분해서 관리한다.

| 상태 | 뜻 |
| --- | --- |
| `IsOccupied` | 이미 누가 도착해서 앉아있음 |
| `IsReserved` | 아직 도착 전이지만 누군가 목적지로 찜해둔 상태 ("예약") |

> **잡았던 버그**: "예약" 개념이 없던 초기 버전에서는, 여러 캐릭터가 같은 순간(`Start()`)에
> 동시에 목적지를 고르면 그 순간엔 아직 아무도 도착 전이라 `IsOccupied`가 전부 false였다.
> 그래서 다들 같은 빈 기물로 몰려가는 것처럼 보였다. 목적지로 고르는 즉시 "예약"해서 다른
> 캐릭터의 후보 목록에서 빠지도록 고쳤다.

```csharp
// 목적지로 고른 즉시 호출 — 도착 전이라도 다른 캐릭터의 후보 풀에서 제외시킨다.
public bool TryReserve(CharacterAgent agent)
{
    if (IsOccupied) return false;
    if (IsReserved && ReservedBy != agent) return false;
    ReservedBy = agent;
    return true;
}
```

`PropManager`는 씬에 딱 하나만 존재하는(`Instance`, **싱글턴 패턴**) 관리자로, "비어있고,
예약도 안 됐고, 직전에 있던 곳도 아니고, 다른 캐릭터 전용(엔딩 기물)도 아닌" 후보 중에서
랜덤으로 하나를 골라준다.

```csharp
public PropSlot GetRandomAvailableProp(CharacterAgent requester, PropSlot exclude)
{
    var candidates = allProps.Where(p =>
        p != null && !p.IsOccupied && !p.IsReserved && p != exclude && p.CanBeUsedBy(requester)
    ).ToList();

    if (candidates.Count == 0) return null;
    return candidates[Random.Range(0, candidates.Count)];
}
```

## 6장. 재화 시스템

`GameEconomy`는 게임 전체가 공유하는 재화 창고다(static 클래스, 씬에 배치 불필요).
**시작값은 코드가 아니라** `Assets/Resources/StartingStateSettings.asset` 에 있고,
`Main` 부팅 때 `GameEconomy.ApplyStartingState()`로 덮어쓴다.

| 재화 | 기획 시작값 (에셋 기본) | 비고 |
| --- | --- | --- |
| MeritPile (공덕) | 1,000 | 무한히 커질 수 있어 `BigNumber` 타입 사용 |
| Yeopjeon (엽전) | 0 | 상점에서 소비 |
| Hyang (향) | 2 | 요괴 소환 시 3개 소모 |
| PurifiedWater (정화수) | 10 | 공양으로 기력 회복 등에 사용 |
| YutToken (윷 토큰) | 5 (최대 5) | 30분마다 1개씩 충전 |
| 공양물 인벤 | 등록 종류 × 각 1개 | `GetOfferingCount` / `TrySpendOffering` |

```csharp
public static int Yeopjeon { get; private set; } = 0;
public static event Action<int> OnYeopjeonChanged;

public static void AddYeopjeon(int amount)
{
    Yeopjeon += amount;
    OnYeopjeonChanged?.Invoke(Yeopjeon);
}

public static bool TrySpendYeopjeon(int amount)
{
    if (amount < 0 || Yeopjeon < amount) return false;
    Yeopjeon -= amount;
    OnYeopjeonChanged?.Invoke(Yeopjeon);
    return true;
}
```

> **get; private set; / event**: `{ get; private set; }`는 "밖에서 값을 읽을 수는 있지만
> 바꾸는 건 이 클래스 안에서만 가능"하다는 뜻. `event`는 "이 값이 바뀔 때마다 관심 있는
> 다른 스크립트들에게 방송해주는 마이크"다.

### 왜 공덕만 따로 BigNumber를 쓸까

공덕은 방치형 게임 특성상 숫자가 끝없이 커질 수 있다. `BigNumber`는 "가수(mantissa) ×
10의 지수(exponent) 제곱" 형태로 저장해서 정밀도 문제를 피한다. 1,000 미만은 숫자
그대로, 그 이상은 **ㄱㄴㄷㄹㅁㅂㅅㅇㅈㅊㅋㅌㅍㅎ** 순서의 한글 자음을 단위처럼 붙인다
(이 프로젝트만의 단위계, 만/억 대신).

### 탭하면 즉시 반응하기 — CharacterTapRouter.cs

캐릭터를 눌렀는지 판단하려면 화면 좌표를 게임 세계 좌표로 바꾸고, 어떤 캐릭터와 가장
가까운지 계산해야 한다. 지도를 드래그하는 동작과 헷갈리지 않도록 "누른 지점에서 손가락이
많이 움직였으면 드래그로 보고 무시한다"는 판정도 넣었다.

```csharp
private void Update()
{
    if (!TryReadPointer(out Vector2 screenPos, out bool isPressed)) return;

    bool justPressed  = isPressed && !wasPressedLastFrame;
    bool justReleased = !isPressed && wasPressedLastFrame;
    wasPressedLastFrame = isPressed;

    if (justPressed)
    {
        pressing = true;
        pressStartScreenPos = screenPos;
    }
    else if (justReleased && pressing)
    {
        pressing = false;
        float moved = Vector2.Distance(screenPos, pressStartScreenPos);
        if (moved <= tapMaxMovePixels) HandleTap(screenPos); // 많이 안 움직였으면 "탭"
    }
}

private void HandleTap(Vector2 screenPos)
{
    if (EventSystem.current != null && EventSystem.current.IsPointerOverGameObject()) return; // HUD 버튼이면 무시

    Vector3 world = targetCamera.ScreenToWorldPoint(new Vector3(screenPos.x, screenPos.y, depth));
    world.z = 0f;

    CharacterAgent nearest = null;
    float nearestDist = tapMaxWorldRadius;
    foreach (var agent in CharacterAgent.All)
    {
        float d = Vector2.Distance(agent.transform.position, world);
        if (d <= nearestDist) { nearestDist = d; nearest = agent; }
    }
    nearest?.OnTapped();
}
```

`EventSystem.current.IsPointerOverGameObject()`는 "지금 누른 지점이 uGUI 버튼 같은 화면
요소 위인지"를 알려준다. 참이면 HUD 버튼을 누른 것이니 캐릭터 탭으로 처리하지 않는다.

## 10장. 씬이 켜지는 순서

`Main.Awake()`가 아래 순서대로 전부 코드로 조립한다.

1. **`Time.maximumDeltaTime = 3600f`** — 백그라운드 탭 대응.
2. **`GameEconomy.ApplyStartingState()`** — `StartingStateSettings`로 재화·인벤 초기화.
3. **EnsureCamera()** — 메인 카메라가 없으면 만들고, `ArtScaleSettings.cameraOrthoSize` 적용.
4. **EnsureLight()** — 조명이 없으면 만든다.
5. **EnsureEventSystem()** — uGUI 버튼 클릭용 (`InputSystemUIInputModule`).
6. **EnsureCharacterTapRouter()** — 탭 감지기를 카메라에 붙인다.
7. **CreateBackground()** — 배경·`MapBounds`·드래그 범위 (`ArtScaleSettings.mapOverscan`).
8. **PropManager 생성** — 기물 관리자.
9. **기물 5개 생성** — `ArtScaleSettings.propScale`.
10. **캐릭터 3마리 생성** — `ArtScaleSettings.characterScale`. 시작 친밀도·기력은 `StartingStateSettings`.
11. **CreateHud()** — 상세화면과 HUD.

`Start()`에서(모든 오브젝트의 Awake가 끝난 다음) 웹지엘 전용으로 로딩 화면을 내린다.

## 12장. 다음에 공부하면 좋을 순서

전체를 한 번에 이해하려 하기보다, 아래 순서로 실제 파일을 열어보는 걸 추천한다. 이 문서의
장 순서와도 같다.
